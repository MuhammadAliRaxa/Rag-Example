Enterprise RAG Production

Welcome to the production documentation for the Enterprise-Grade Retrieval-Augmented Generation (RAG) system. This codebase implements a highly modular, performant, and evaluatable RAG design focusing on deduplicated multi-strategy chunk loading, dual-dense/sparse indices fusion search, contextual reranking, and citation-accurate Gemini outputs.

💡
System Design Highlights: The architecture decouples the database, retrieval mechanism, generation flow, and conversational memory, allowing easy replacement of sub-components (e.g., swapping local embeddings for OpenAI, or ChromaDB for Pinecone).
⚙️

Ingestion & Chunking

Advanced loaders parsing PDFs, HTML, and Markdown, offering sliding Fixed-size, Recursive header-aware, and Semantic embedding similarity boundary chunking.

Dual Hybrid Search

Ingestion & Chunking Pipeline

The ingestion process transforms documents (PDF, Markdown, HTML) into rich, metadata-tagged text chunks, filters out duplicate data, and indexes them in a dual search structure.

Document Loading & Extraction

Implemented in src/ingestion/loaders.py and src/ingestion/parsers.py, the loader accepts a file pathway, determines the extension, and extracts structured text. Supported file extensions include .txt, .md, .html, and .pdf.

Each page/section produces a RawDocument containing:

  • content: Extracted raw text.
  • source_path: Origin filename.
  • raw_hash: MD5 fingerprint computed from the text.
  • metadata: Structured dictionary housing keys like page_number or section_heading.

Supported Chunking Strategies

Found in src/ingestion/chunkers.py, the chunking layer supports three configurable techniques:

Strategy Name Class Name Methodology
Fixed-Size FixedSizeChunker Tokens are encoded via tiktoken and split based on a sliding threshold (default 512 tokens) and window overlap (default 64 tokens).
Recursive RecursiveChunker Text is recursively split using hierarchical boundaries (Headers, Paragraphs, Sentences, Words) to fit inside token budgets.
Semantic SemanticChunker Splits text into sentences, computes adjacent sentence embedding cosine similarity, and splits chunks only when similarity drops below threshold (default 0.75) or token size limit is reached.
src/ingestion/chunkers.py (Semantic Similarity Check)

similarities = []
for i in range(len(embeddings) - 1):
    sim = EmbeddingModelWrapper.cosine_similarity(embeddings[i], embeddings[i + 1])
    similarities.append(sim)

# Group sentences into topic chunks based on drops
for i, sim in enumerate(similarities):

    candidate_text = " ".join(current_group + [next_sentence])

        grouped_chunks_texts.append(" ".join(current_group))
        current_group = [next_sentence]

        current_group.append(next_sentence)

Deduplication Engine

To avoid indexing repeating context, src/ingestion/dedupe.py utilizes a high-efficiency two-stage filter before committing records to ChromaDB:

  1. Exact MD5 Hash Check: Keeps track of text hashes processed during execution. If an exact duplicate matches, the pipeline skips it.
  2. Near-Duplicate Similarity Check: Queries ChromaDB for the closest vector match (Top-1 search). If cosine similarity exceeds settings.SEMANTIC_SIMILARITY_THRESHOLD (default: 0.95), the chunk is rejected as a near-duplicate.

Dual Search Storage Manager

To enable hybrid dense + sparse search, src/ingestion/vectorstore.py wraps two databases:

  • ChromaDB: Handles embedding storage and retrieves similar context based on Cosine similarity (configured via HNSW index spacing).
  • BM25 Okapi Index: Custom serialized Python pickle file (bm25_index.pkl) storing tokenized document frequencies to resolve keyword searches.

The VectorStoreManager executes updates atomically, synchronizing insertions across both databases.

Hybrid Search & Fusion

Retrieval merges the semantic depth of dense embeddings with the exact text matching of sparse term indexes using Reciprocal Rank Fusion (RRF), then optimizes with contextual reranking.

Vector Search

Translates user query using the embedding model and queries the Chroma collection. Returns candidate chunks with their respective cosine distance values.

BM25 keyword

Tokenizes the query and calculates BM25 term frequency scores across all ingested texts. Excels at retrieving product keys, code segments, or exact names.

RRF Fusion (Hybrid)

Fuses dense and sparse rankings by summing the reciprocal rank of item rankings. This ensures robust retrieval regardless of wording choice.

src/retrieval/hybrid.py (Reciprocal Rank Fusion) 
def search(self, query: str, query_vector: List[float], top_k: int = 5, rr_k: int = 60) -> List[Dict[str, Any]]:
    """Reciprocal Rank Fusion (RRF) implementation."""
    vec_results = self.vector_engine.search(query_vector, top_k=top_k)
    kw_results = self.keyword_engine.search(query, top_k=top_k)

    scores: Dict[str, float] = {}
    chunks_map: Dict[str, Dict[str, Any]] = {}

    for rank, item in enumerate(vec_results):
        cid = item["chunk_id"]
        scores[cid] = scores.get(cid, 0.0) + (1.0 / (rr_k + rank + 1))
        chunks_map[cid] = item

    for rank, item in enumerate(kw_results):
        cid = item["chunk_id"]
        scores[cid] = scores.get(cid, 0.0) + (1.0 / (rr_k + rank + 1))
        chunks_map[cid] = item

    sorted_chunks = sorted(scores.items(), key=lambda x: x[1], reverse=True)[:top_k]
    return [chunks_map[cid] for cid, _ in sorted_chunks]

Reranking & Expansion

  • Query Rewriter (query_rewriter.py): Rewrites short messages based on chat session context into standalone queries, and generates expansion variations for deeper retrieval coverage.
  • Cross-Encoder Reranker (reranker.py): Reranks fused candidates using a joint query-passage neural model to output the most contextually relevant chunks first.

LLM Generation & Citations Mapping

LLM Client Wrapper

Integrated in llm_client.py. Configures Google's gemini-1.5-flash. In local dev, if GEMINI_API_KEY is absent, it seamlessly falls back to a simulated response to allow offline code testing.

Citation Mapper

Defined in citation_mapper.py. Parses references matching [Chunk <id>], validating them against the loaded chunks list to construct structured citations outputs.

Multi-Session Chat Memory

Chat memory is isolated from the application state, enabling scalable deployments. In src/memory/conversation_store.py, context sessions are handled outside of the main process:

  • Redis Connection: Backed by Redis via REDIS_URL connection patterns. Messages are read and pushed as JSON-serializable list collections under session keys.
  • Safe Fallback Mode: In environments without an active Redis service, the store falls back to a standard in-memory dictionary. This avoids local runtime crashes while logs alert administrators to configure a persistent memory layer.

REST API Endpoints

FastAPI provides high-performance asynchronous endpoints, complete with Pydantic request models and CORS support.

GET /health

Returns API statuses and verification of the backing database and index caches.

cURL Command 
curl -X GET http://localhost:8000/health
POST /api/v1/ingest

Ingests uploaded file into ChromaDB and BM25 index with a designated chunking strategy.

Query Parameters: strategy (optional, defaults to settings config: fixed, recursive, or semantic).

cURL Command 
curl -X POST http://localhost:8000/api/v1/ingest?strategy=recursive \
  -F "file=@/path/to/document.pdf"
POST /api/v1/retrieve

Retrieves chunks matching a query without querying an LLM model.

Request Payload JSON Schema 
{
  "query": "What is self-attention?",
  "top_k": 3,
  "strategy": "hybrid" // "hybrid", "vector", or "keyword"
}
cURL Command 
curl -X POST http://localhost:8000/api/v1/retrieve \
  -H "Content-Type: application/json" \
  -d '{"query": "attention mechanism", "top_k": 3, "strategy": "hybrid"}'
POST /api/v1/chat

Main conversational endpoint. Appends history to session memory, executes query RRF, constructs templates, generates Gemini LLM outputs, maps source citations, and saves assistant responses to storage.

Request Payload JSON Schema 
{
  "session_id": "session_user_9921",
  "message": "Explain how the Reranker component is implemented."
}
cURL Command 
curl -X POST http://localhost:8000/api/v1/chat \
  -H "Content-Type: application/json" \
  -d '{"session_id": "session_99", "message": "What is Reciprocal Rank Fusion?"}'

Evaluation Suite

The codebase supports automated evaluation of retrieval precision and answer quality in src/evaluation/.

  • Golden Dataset: Managed by GoldenDatasetLoader. Hosts pairs of validation questions, context identifiers, and target ground truths.
  • Retrieval Metrics (retrieval_metrics.py): Measures Precision@K, Recall@K, and Mean Reciprocal Rank (MRR) to analyze indexing and fusion performance.
  • Answer Quality Metrics (answer_metrics.py): Evaluates LLM responses, focusing on Faithfulness (checking if claims map directly to retrieved chunks) and Answer Relevance.

To run the evaluation benchmarks from terminal, call:

Terminal Command 
make eval

Getting Started & Setup Steps

Follow these steps to run the RAG Production system locally or inside container environments.

1. Configuration Settings

Configure environment settings in the .env file. A template is provided in .env.example.

rag-production/.env 
APP_NAME="RAG Production API"
ENV="development"
DEBUG=True

# LLM Providers (Required for generation)
GEMINI_API_KEY="your-gemini-api-key-here"
DEFAULT_MODEL="gemini-1.5-flash"

# Vector Database
VECTOR_DB_TYPE="chroma"
CHROMA_PERSIST_DIR="./vectorstore/chroma"
BM25_INDEX_PATH="./vectorstore/bm25_index.pkl"

# Redis Chat Memory
REDIS_URL="redis://localhost:6379/0"

# Ingestion Pipeline
CHUNK_STRATEGY="recursive"  # fixed, recursive, semantic
CHUNK_SIZE=512
CHUNK_OVERLAP=64
SEMANTIC_SIMILARITY_THRESHOLD=0.95
SEMANTIC_SPLIT_THRESHOLD=0.75

2. Makefile Automation Commands

The root folder contains a Makefile to manage tasks. Here are the core targets:

Command Action
make serve Starts the FastAPI server with uvicorn hot-reloading at port 8000.
make ingest FILE=data/raw/sample.pdf Runs the file ingestion script. If FILE is omitted, it parses all documents under data/raw/.
make eval Runs the evaluation suite on the dataset, outputting precision metrics.
make test Runs pytest unit and integration tests under the tests/ directory.
make clean Deletes Python cached compiled directories (__pycache__).
⚠️
GPU/MPS Acceleration: Embedding and Cross-Encoder calculations automatically detect and use Apple Silicon MPS or CUDA devices if PyTorch dependencies are available.
